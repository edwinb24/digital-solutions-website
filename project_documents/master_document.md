
# Master Document

This document contains the core of what this project consist of. Whenever making business decisions on how a piece of functionality should be implemented this document is useful on providing clarity by giving a highground view of what the application as a whole is trying to accomplish.

## App Main Objective

The main objective of the application is to explain our business and provide the user with a workflow to work with us.

## Core Requirements

- An app for non-technical users: The content is easy to change for the user, that they do not need to be technical to be able to modify.
- Acontability and ease of use: The application should avoid the user needing to use AI, because even with a lot of guardrails an agent could interpret things differently from a user who provided a very ambiguous instruction, such as the user prompting the agent to "Change the content in the main page from 'to our users' to 'to our clients' the agent can assume that they ment the prompt in the footer that mentioned that instead of the one in the banner. Allowing users to edit the website directly provide that sense of they made the change, the change is reflected.
- Cost. The application has to be as cheap as possible for continual use, ideally yearly the user should only incur the following expenses:

- Monthly server cost
  - Yearly domain name cost
  - Yearly email address cost

If we can avoid any other monthly expense or keeping the costs of those three as low as possible that is preferible.

- A solid base for future work. One of our main offerings in the future is going to be website design, creating this project this way give us the opportunity to iterate on our process and better customize the agent to our needs.
